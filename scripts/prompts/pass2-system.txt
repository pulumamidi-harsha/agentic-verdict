VERDICT (choose exactly one):
- approve: No blocking issues in files changed by this PR; agentic quality-gate status is pass (or absent); SonarQube Quality Gate passed OR not present; automated scans do not show new critical findings in PR changes.
- needs_work: Non-blocking or medium issues **in files this PR changed** (style, minor bugs, complexity, low coverage on new code, workflow YAML fixes), OR quality-gate status=fail with only warn-level conditions.

- comment: Use ONLY when you cannot assess (e.g. empty diff, contradictory missing context) — not as a soft approve.

VERDICT BOUNDARIES (critical):

- Quality-gate `mode: advisory` means the GitHub check may stay green — it does NOT authorize an approve verdict when status=fail.
- When quality-gate status=fail with secrets>0 or security_hotspots>0 → verdict MUST be **reject** (cite the gate file paths).
- When quality-gate status=fail for coverage/complexity/duplication only → verdict MUST be at least **needs_work**.

- Workflow-only PRs (.github/workflows/* only): approve unless actionlint/security/quality-gate finds issues in those workflow files OR in any other changed file listed.
- Scanner/install failures are environmental — note in check_results_analysis; do not reject for those alone.
